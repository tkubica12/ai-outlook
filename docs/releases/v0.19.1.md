# Tomlook v0.19.1

This release fixes MSX sign-in, restores automatic Insights, which have
failed since v0.17.1, and cleans up Messages about meetings that have already
ended. These are changes since
[v0.19.0](https://github.com/tkubica12/ai-outlook/releases/tag/v0.19.0).

## MSX signs in again

Dataverse admits only
[allowed MCP clients](https://learn.microsoft.com/en-us/power-apps/maker/data-platform/data-platform-mcp-disable#configure-and-manage-the-dataverse-mcp-server).
The Azure CLI token Tomlook used was rejected with HTTP 403, and the device
code fallback is blocked by Conditional Access (error 530033).

MSX now uses its own browser sign-in with the public client that GitHub
Copilot and VS Code use (authorization code with PKCE, scope `mcp.tools`):

- **Sign in to MSX** opens Microsoft sign-in in your default browser.
  Microsoft redirects to `https://vscode.dev/redirect`, which hands the result
  to a one-time listener on `127.0.0.1`. Tomlook accepts it only with the
  expected nonce.
- The refresh token is saved in `msx-login.db`, encrypted for your Windows
  user (DPAPI). Later starts renew silently and never open a browser.
- **Disconnect** removes the saved MSX sign-in.
- Power BI (Azure consumption) still uses your Azure CLI sign-in.

MSX stays read-only.

## Automatic Insights work again

Since v0.17.1, the built-in preparation prompt has been longer than the
8000-byte limit for questions, so every Insights preparation failed before it
was sent. The limit now applies only to your own questions, not to the
built-in prompt.

Failed meetings also no longer pile up:

- A failed automatic preparation is retried up to three times with backoff,
  as before, and then once a day instead of never.
- Meetings that already failed are retried after the upgrade. A changed
  meeting or changed preparation settings retry immediately.
- A meeting leaves the queue once it is over.
- A failed **Research now** request still waits for **Retry**.

## Messages about ended meetings disappear

- Unsent, failed or unconfirmed calendar changes to a meeting that has already
  ended expire automatically and leave Messages. They are never submitted
  later.
- Proposed edits to saved Insights or notes and follow-ups stay, because they
  belong after the meeting.
- **Event creation** entries disappear once every time they cover has passed,
  unless the creation is still running.
- Finished entries older than 30 days for ended meetings are now removed
  regularly, not only after a successful preparation.

## Download and upgrade

v0.8.0 and later can install this release after signed-update verification
when you choose **Restart now** in Settings -> Updates or exit Tomlook.
Otherwise download `Tomlook-v0.19.1-win-x64.zip`, fully exit Tomlook including
its tray instance and replace `Tomlook.exe`. Keep the existing
`%LOCALAPPDATA%\Tomlook` profile.

After the upgrade, use **Sign in to MSX** once. The release includes
checksums, third-party notices and a signed update manifest.

## Verification scope

Offline tests cover:

- MSX browser sign-in: PKCE, the redirect and nonce checks, encrypted token
  storage, silent renewal and **Disconnect**;
- the preparation prompt passing the question limit while your own long
  questions are still rejected;
- daily retries of exhausted automatic failures, while failed **Research
  now** requests and a halted queue keep waiting;
- expiry of unfinished changes to ended meetings, which keeps notes edits and
  follow-ups, and hiding ended event creations in Messages.

Clippy, app tests and integration tests passed. MSX sign-in and a read-only
Dataverse query were verified live. Automatic Insights were not observed end
to end against live services as part of this verification.

Two tests still fail for reasons unrelated to these changes:

- a worker recommendation refresh test that does not expect a field added in
  v0.17.1;
- a scheduler test whose fixed calendar fixture ended on 16 November 2026, so
  it no longer produces jobs.
