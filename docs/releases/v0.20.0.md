# Tomlook v0.20.0

This release migrates Tomlook from `github-copilot-sdk` v1 to **Microsoft
Copilot SDK 2** (`copilot-sdk` 2.0.4, protocol 4) with native in-process runtime
hosting. These are changes since
[v0.19.2](https://github.com/tkubica12/ai-outlook/releases/tag/v0.19.2).

## Microsoft Copilot SDK 2 and in-process runtime

- Upgraded the Rust SDK crate from `github-copilot-sdk` `1.0.18-preview.0` to
  Microsoft's official successor `copilot-sdk` `2.0.4` (`local-runtime`
  feature, no proprietary runtime bundled into `Tomlook.exe`).
- Migrated client and session configuration to the v2 protocol-4 contract:
  explicit `ClientMode::Empty`, grouped `ClientOptions` (`github`,
  `observability.disable_client_telemetry = true`), `RuntimeConnection`, and
  grouped `CreateSessionOptions` (`inference`, `policy`, `tools`, `mcp`,
  `events`, `permissions`, `hooks`) with per-session isolated `workspace`
  working directories.
- Added native in-process hosting (`RuntimeConnection::InProcess` over the C
  ABI) when `connections.json` points to an installed protocol-4
  `runtime.node`, `copilot_runtime.dll`, or a `copilot-runtime.exe` beside
  `runtime.node`, dramatically reducing startup latency while preserving DPAPI
  token isolation, `Empty` mode, and disabled shared keychain/telemetry.
- Retained `RuntimeConnection::SpawnedStdio` fallback for standalone protocol-4
  `copilot.exe` installations.

## Upgrading

Microsoft Copilot SDK 2 requires a **protocol-4** Copilot runtime
(1.0.115+/1.0.117+). In `%LOCALAPPDATA%\Tomlook\connections.json`, ensure
`runtime` points to a protocol-4 `runtime.node`, `copilot_runtime.dll`,
`copilot-runtime.exe`, or updated `copilot.exe`.

v0.8.0 and later can install this release after signed-update verification
when you choose **Restart now** in Settings -> Updates or exit Tomlook.
Otherwise download `Tomlook-v0.20.0-win-x64.zip`, fully exit Tomlook including
its tray instance and replace `Tomlook.exe`. Keep the existing
`%LOCALAPPDATA%\Tomlook` profile.

The release includes checksums, third-party notices and a signed update
manifest.

## Verification scope

- Added isolation tests covering native in-process hosting (`runtime.node` and
  adjacent `copilot-runtime.exe`) alongside standalone child-process hosting.
- Ran `cargo clippy --all-targets --locked --offline` with zero warnings, all
  `copilot::`, `msx::`, `chat_cache::`, `context::`, `telemetry::`, `ai::`, and
  integration `isolation` / `ai` tests passing.
- Verified live end-to-end in-process startup, protocol-4 handshake, DPAPI
  token authentication, session creation, disconnect, and shutdown with
  `sdk-probe` against `runtime.node` `1.0.115-7` (~660 ms total).
- The two unrelated pre-existing failing tests noted in
  [v0.19.1](https://github.com/tkubica12/ai-outlook/releases/tag/v0.19.1) are
  unchanged.
