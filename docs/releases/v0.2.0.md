# Tomlook v0.2.0

This release improves recommendations and meeting actions in the native Windows
calendar. These are changes since [v0.1.0](https://github.com/tkubica12/ai-outlook/releases/tag/v0.1.0),
not a new calendar migration or assistant rewrite.

## Clearer, quieter recommendations

- A neutral status-bar bell replaces the warning triangle.
- A larger master-detail window separates the recommendation list from the
  selected action. Previous/Next buttons and Alt+Up/Alt+Down support navigation.
- Each detail clearly separates what is proposed, which meeting it concerns,
  and why. Category transitions share an aligned baseline and a native arrow.
- Technical checks and route/availability caveats stay under Details instead
  of overwhelming the main recommendation.
- Meeting titles open the calendar detail and saved Insights without starting
  fresh AI research.

## Better categories, travel and preparation

- `office` means the user's home/employer office, not a customer's or partner's
  premises. Offsite visits use `mimo office` when that category exists.
- Arrival and departure travel reserves are considered independently. Existing
  travel blocks suppress duplicates only on their respective side.
- Confirmed travel/preparation blocks are uncategorized. An explicitly uncertain
  parent can pass on its uncertainty category.
- Substantial deck, demo or workshop preparation can use a 60-180-minute block
  in an earlier workday, up to fourteen days before the meeting. Short final
  reviews still use a nearby gap.
- Skip is remembered across research updates, meeting metadata changes and
  application restarts. Different category targets and arrival/departure
  travel remain separate decisions.
- Old category/travel drafts generated under the previous rules expire.
  Manual actions and unresolved write outcomes remain available for review.

## More useful conflict and missing-material advice

- Conflicts show named counterpart meetings, their full local date/time ranges,
  and the overlap. Raw model-written UTC times no longer drive this display.
- Reciprocal conflicts appear once; separate conflicts remain visible.
  Skipping a conflict pair does not hide unrelated pairs.
- Conflict cards offer the same role-appropriate tentative, decline,
  cancel/delete actions as the meeting menu, using one compact confirmation.
- Missing-material advice identifies actual invitation contacts and a concrete
  question to ask. The organizer and same-email-domain attendees are prioritized
  without assuming agenda ownership.
- Verified sign-in and primary-mail aliases are excluded from contact suggestions.
  Tomlook does not contact participants automatically.

## Calendar-response fixes and responsiveness

- Invitation-response bodies follow the discovered WorkIQ object/string schema.
  Empty optional comments are omitted; nonempty comments and the organizer
  notification choice are preserved.
- Definitive provider failures retain HTTP status and a safe, allowlisted error
  code without storing private provider messages or arbitrary response bodies.
- Unknown outcomes are never automatically replayed. A rejected write requires
  a fresh user confirmation before another submission.
- Recommendation deduplication and derived inbox data are computed and cached
  on the storage worker. The list is virtualized and only one detail is rendered,
  keeping calendar interaction independent of background AI work.
- English and Czech labels cover the new recommendation and action controls.

## Download and upgrade

Download `Tomlook-v0.2.0-win-x64.zip`, extract it, and run `Tomlook.exe`.
This is a portable, unsigned Windows 10/11 x64 application, not an installer.
Its Windows file/product version is `0.2.0`. The archive contains only the
executable, project license and third-party/font notices; checksums are supplied
in `SHA256SUMS.txt`.

When upgrading, fully exit Tomlook, including its tray instance, before replacing
the executable. Your existing `%LOCALAPPDATA%\Tomlook` profile remains separate
from the archive; do not delete it to upgrade.

The current [Microsoft Visual C++ v14 Redistributable (x64)](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)
is required. Neither it nor the separately installed Copilot CLI runtime is
bundled. See [native setup](https://github.com/tkubica12/ai-outlook/blob/v0.2.0/native/README.md)
for connection requirements.

## Verification scope and remaining limits

Tentative acceptance has been verified against a live calendar with organizer
notifications disabled. Accept and decline share the corrected request builder
but have not been live-retested for this release. WorkIQ access and mutation
permission still depend on account access and tenant policy.

Travel durations and real-world availability are estimates, not live traffic
guarantees. Category choices still come from cached calendar categories.
The broader Ask AI scheduling redesign and long-run acceptance gates are not
claimed as completed by this release.
