# Tomlook v0.18.0

This release adds a dedicated invitation queue, clear calendar focus for the
request being reviewed, and a smaller, calmer status bar. These are changes
since [v0.17.1](https://github.com/tkubica12/ai-outlook/releases/tag/v0.17.1).

## Invitations without searching the calendar

**Invitations** in the sidebar and command palette collects unanswered
requests for the next six months, independently of the displayed period.
**Important**, **Other** and **Snoozed** separate useful requests from noise.
The badge counts important invitations, not every corporate broadcast.

Priority is local and deterministic: confirmed customer domains, selected
close-team membership and explicit organizer preferences are strong signals.
Unknown external organizers or participants are weaker signals, never proof
of a customer or another tenant. Large broadcasts, optional attendance and
explicit broadcast wording normally go to Other; confirmed customer context
and explicit organizer highlights take priority.

Right-click to snooze a request, highlight or quiet its organizer, or quiet
an invitation/series. These choices change only Tomlook. The queue refreshes
about every three minutes while WorkIQ is connected, without requiring an
AI connection. Offline state and refresh errors remain visible.

## See exactly which invitation you are reviewing

Click a request to show its day and neighboring days alongside normal meeting
details, or choose **Whole week**. Display filters are temporarily bypassed.
The chosen invitation has a strong accent outline, tinted background and
full timeslot height, with **Selected invitation** when space permits.
It stays highlighted while you inspect a conflicting meeting; selecting a
different queue item moves the highlight.

Returning to **Calendar** restores the previous dates and selection. Accept,
Tentative and Decline reuse the existing confirmation, colored category
choices and verified write path. Recurring invitations are grouped for
browsing, but a response applies only to the displayed occurrence.
Opening an invitation never sends a response.

## Configure your close team

**My team** can explicitly discover directory-group candidates from bounded
historical-mail recipient headers. Discovery does not enable new groups.
Select the appropriate groups or add individual people and exclusions;
enabled groups refresh their transitive membership daily.

Incomplete or failed membership reads keep the last good cache and show an
error. Team choices and priority rules are account-specific, stay in the local
profile, and never modify directory membership or go to AI.

Filtered invitation reads do not establish calendar coverage. A **No conflicts**
result requires complete, recently refreshed calendar data; missing coverage
remains unknown, never free time.

## Compact, quieter status bar

Connection indicators use short names and separated icons instead of long
sentences. Ordinary states use neutral text; only disconnections and problems
use subdued red. Calendar, synchronization and Insights counts use icons and
numbers, with full explanations on hover and through accessibility.

The footer adapts to narrow windows and keeps connection dialogs, activity,
messages, setup, updates and the version on one compact line.

## Download and upgrade

v0.8.0 and later can install this release after signed-update verification
when you choose **Restart now** in Settings -> Updates or exit Tomlook.
Otherwise download `Tomlook-v0.18.0-win-x64.zip`, fully exit Tomlook including
its tray instance and replace `Tomlook.exe`. Keep the existing
`%LOCALAPPDATA%\Tomlook` profile.

The release includes checksums, third-party notices and a signed update
manifest.

## Verification scope

Offline checks cover invitation eligibility and priority, recurrence grouping,
snoozes, account isolation, complete membership, stale results, calendar
coverage, existing response approvals, pinned calendar emphasis and responsive
footer layout. Native visual inspection uses fictional data in both light and
dark themes. No live RSVP write was performed for release verification.

The existing `invitation_previews_never_enter_preparation_or_meeting_questions`
test still fails because the unchanged preparation prompt exceeds its existing
8,000-byte question limit. It is excluded from the targeted invitation-library
run, not reported as passing; this release does not claim a full-suite pass.
