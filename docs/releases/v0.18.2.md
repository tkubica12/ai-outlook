# Tomlook v0.18.2

This release repairs GitHub Copilot sign-in while preserving Tomlook's
separate identity and encrypted credential storage. These are changes since
[v0.18.1](https://github.com/tkubica12/ai-outlook/releases/tag/v0.18.1).

## Independent, encrypted Copilot sign-in

The SDK's Empty mode disables the shared system keychain to isolate Tomlook
from ordinary Copilot credentials. Runtime-managed sign-in could consequently
request plaintext token storage, which Tomlook refused.

Tomlook now performs its own device-code sign-in using the Copilot CLI public
OAuth application. Choose **GitHub Copilot -> Sign in**, open
`https://github.com/login/device` and enter the displayed code. The browser
and terminal do not open automatically, and **Cancel AI sign-in** stops the
flow.

After verifying the GitHub identity, Tomlook saves its token in
`copilot-login.db`, protected with current-user Windows DPAPI. It passes only
that token explicitly to its isolated SDK child process. Empty mode, disabled
shared-keychain access, configuration isolation and rejection of ambient
Copilot or `gh` credentials remain in place. There is no plaintext fallback.

Sign-in failures now show an explicit failure instead of the misleading
generic "AI sign-in finished" message. Device-code and completion messages
are available in English and Czech.

## Download and upgrade

v0.8.0 and later can install this release after signed-update verification
when you choose **Restart now** in Settings -> Updates or exit Tomlook.
Otherwise download `Tomlook-v0.18.2-win-x64.zip`, fully exit Tomlook including
its tray instance and replace `Tomlook.exe`. Keep the existing
`%LOCALAPPDATA%\Tomlook` profile.

After upgrading, sign in once from Tomlook to create its encrypted record.
The older isolated `copilot login` workaround is no longer used. Legacy
runtime login files are neither imported nor automatically removed. The
explicit `copilot_credential_env` configuration remains supported.

The release includes checksums, third-party notices and a signed update
manifest. No dependency or external Copilot CLI runtime upgrade is required
by this change.

## Verification scope

Offline verification covers DPAPI round trips and tamper rejection,
preserving an existing sign-in when a replacement is cancelled, cancellation
and shutdown before and during authorization, device-code polling and OAuth
request scopes, explicit SDK token injection, rejection of shared credentials,
failure reporting and the bilingual sign-in dialog. Production Clippy checks
passed with warnings denied.

Live OAuth authorization with a user account and a model request were not
performed as part of this verification. This release does not claim a
full-library-suite pass; the pre-existing preparation-prompt length failure
documented in v0.18.1 is outside this change.
