# Tomlook v0.5.0

This release adds native appointment creation and explicitly approved travel
reserves, including a right-click action for existing owned meetings. These are
changes since
[v0.4.0](https://github.com/tkubica12/ai-outlook/releases/tag/v0.4.0).

## Create appointments directly in the calendar

- Click an empty timeline slot for a 30-minute appointment, or drag either
  direction to select its start and end in 15-minute steps.
- The timeline exposes all 24 hours and initially scrolls to 08:00. Mouse-wheel
  and scrollbar navigation remain available while dragging selects time.
- **New event** provides a keyboard-accessible entry point in every view.
- A compact English/Czech editor shows time sliders, title, optional description,
  directly selectable categories, a **Private** lock and optional **Teams**.
- Enabling Private automatically selects an existing `osobni`/`personal`
  category, including the accented Czech spelling. If none exists, the editor
  warns instead of inventing a category.
- Teams creation checks the calendar's supported online-meeting providers. A
  verified join URL is available in meeting details after successful creation.

Private items use Outlook private sensitivity. Delegates explicitly authorized
to view private items may still see their details. This editor does not add
attendees, reserve rooms, create recurrence or send invitations; use Outlook for
those workflows.

## Travel before and after a meeting

Enable **Add travel blocks before and after** when creating an appointment.
Both adjacent busy reserves default to 30 minutes each, adjustable from 15 to
180 minutes in 15-minute steps. They are uncategorized, have no attendees or
Teams link, and inherit the appointment's private status.

For an existing owned, timed meeting, right-click and choose **Add travel blocks
before and after**. A compact confirmation shows the original meeting and both
reserve intervals with the same duration slider. Only the two reserves are
created: the original meeting is neither copied nor edited.

Existing-meeting travel requires verified organizer and privacy metadata.
Attendees' meetings, cancelled events, all-day items and recurrence series
masters are not eligible. Fresh provider reads check the original meeting and
complete availability coverage before writing; occupied intervals, including
existing travel reserves, block the operation.

## Explicit approval and durable outcomes

Closing the editor or pressing Escape never writes. The displayed event and
optional reserves require explicit confirmation, bound to the connected account
and, for existing-meeting travel, the original meeting snapshot.

Each part has a distinct transaction ID and is read back before the next part
is submitted. Progress and outcomes persist under **Messages > Event creation**.
Interrupted or unknown outcomes are never automatically replayed. If a later
reserve fails, verified earlier items remain; there is no automatic rollback.
Check Outlook before recreating anything after an uncertain result.

Creation shares the existing serialized calendar-write lane and does not consume
the AI research budget. No autonomous calendar creation is added.

## Download and upgrade

Download `Tomlook-v0.5.0-win-x64.zip`, extract it, and run `Tomlook.exe`.
This is a portable, unsigned Windows 10/11 x64 application, not an installer.
Its Windows file/product version is `0.5.0`. The archive includes the executable,
project license and third-party/font notices. `SHA256SUMS.txt` supplies checksums
for the executable and ZIP.

Fully exit Tomlook, including its tray instance, before replacing the executable.
Copy any ordinary in-memory chat answers you need first. Keep the existing
`%LOCALAPPDATA%\Tomlook` profile; it is not part of the download and must not be
deleted to upgrade.

The current [Microsoft Visual C++ v14 Redistributable (x64)](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)
is required. Live AI still requires the separately installed Copilot CLI
runtime. See [native setup](https://github.com/tkubica12/ai-outlook/blob/v0.5.0/native/README.md)
for connection requirements.

## Verification scope and remaining limits

Native regression checks cover time selection, bilingual creation and travel
confirmation, privacy/category behavior, DST boundaries, exact write/read-back
verification, approval recovery, stale parents, collisions and partial failures.
They include the actual right-click-to-confirmation UI path and checks that
existing-meeting travel never creates or updates the original meeting.

These checks use offline fixtures and provider fakes. No live user calendar
events were created during development, and live tenant write permissions or
Teams-link generation have not been proven by those checks. WorkIQ access and
online-meeting support remain subject to the account, connector and tenant
policy. This release does not claim all broader live-provider, accessibility or
long-run acceptance gates complete.
