# Tomlook v0.6.1

This patch clarifies AI provider status and improves Azure device-code sign-in
feedback. These are changes since
[v0.6.0](https://github.com/tkubica12/ai-outlook/releases/tag/v0.6.0).
Calendar-write behavior and stored-data formats are unchanged.

## Clear provider names

The status bar and connection dialog now distinguish **GitHub Copilot** and
**Foundry**, rather than calling the connections AI and Auto.

- GitHub Copilot generates answers and meeting analyses in every answer mode.
- Foundry runs Microsoft-Decision-1 only to select Quick or Thorough for Auto.
- **Auto** remains an answer mode, not a separate provider. A Foundry sign-in
  problem does not mark Copilot disconnected or prevent manual mode selection.

Connection repair actions and Czech/English status text use the same names.
Foundry's signed-in state means Azure authentication was verified; deployment
access is still checked by an actual routing request.

## Device-code sign-in feedback

The fixed Microsoft sign-in link is visible as soon as sign-in starts, with a
spinner and an explicit waiting message. If Azure CLI does not supply a usable
code within 60 seconds, Tomlook stops that attempt and shows a retryable error.
The existing overall expiry and cancellation controls remain available.

Windows MSI Azure CLI runs through its own isolated Python with unbuffered
output. A failure to deliver the code to the interface is now an explicit error
instead of a log-only condition. Duplicate sign-in/check requests report the
active operation rather than leaving a misleading starting message.

Interactive sign-in remains an explicit action. It never starts automatically,
does not change persistent CLI settings and does not replay a failed question.
The existing Azure CLI profile is used; completing sign-in may change its
default account. Token reads still specify and verify the configured tenant
and subscription.

## Download and upgrade

Download `Tomlook-v0.6.1-win-x64.zip`, extract it, and run `Tomlook.exe`.
This is a portable, unsigned Windows 10/11 x64 application, not an installer.
Its Windows file/product version is `0.6.1`. The archive contains the executable,
project license and third-party/font notices. `SHA256SUMS.txt` supplies checksums
for the executable and ZIP.

Fully exit Tomlook, including its tray instance, before replacing the executable.
Keep the existing `%LOCALAPPDATA%\Tomlook` profile. Runtime and connection
requirements are unchanged; see
[native setup](https://github.com/tkubica12/ai-outlook/blob/v0.6.1/native/README.md).

## Verification scope and remaining limits

Regression coverage includes provider status, bilingual connection controls,
bounded first-code waiting, code delivery before stream closure, visible
delivery failures, unbuffered MSI CLI arguments and cancellation.

One explicitly authorized live Azure CLI diagnostic obtained a device-code
prompt in an isolated temporary profile and was then cancelled without
completing sign-in. The original starting-state stall was not reproduced.
This release improves bounded progress and failure handling; it does not claim
that a completed live sign-in or tenant-specific Foundry deployment access
has been verified.
