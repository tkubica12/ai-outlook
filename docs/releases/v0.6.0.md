# Tomlook v0.6.0

This release adds Follow, personalized post-meeting AI notes, configurable
prompts and a reorganized settings window. It also improves connection recovery,
calendar clarity and stale recommendation handling. These are changes since
[v0.5.0](https://github.com/tkubica12/ai-outlook/releases/tag/v0.5.0).

## Follow without attending

Right-click an invitation and choose **Follow** (**Sledovat** in Czech).
The action runs directly, without a confirmation dialog. Ineligible meetings
keep the action visible but disabled with an explanation.

Tomlook simulates Follow using its reserved category and `showAs=free` in one
verified calendar update. It preserves other categories and the invitation
response, keeps the event in the calendar and does not notify the organizer.
It is not Outlook's native Follow response. **Stop following** removes the
category without guessing or restoring an earlier busy status.

Declining invitations now defaults to not notifying the organizer; that option
remains selectable before confirmation.

## Personalized notes after a meeting

Tomlook checks ended meetings in a rolling seven-day window. Accepted meetings,
meetings you organize and followed invitations are eligible. When an accessible,
occurrence-matched transcript appears, AI can combine it with the meeting chat
to produce notes emphasizing mentions of the signed-in user, assigned work,
technical takeaways and original shared-material links.

Successfully saved notes are processed once and are not polled or regenerated
automatically, including after prompt changes. Meetings older than seven days
are no longer checked automatically. Missing transcripts and provider errors
are explicit states, not empty successful notes.

Past meeting details distinguish notes from upcoming preparation. Calendar
badges indicate ready preparation or ready post-meeting notes. Automatic
upcoming preparation is limited to accepted or organized meetings, excludes
Follow and can safely recover interrupted automatic read-only research.

## Settings and a quieter calendar

- The gear opens a larger, resizable settings window with left navigation.
  **Display** groups language, light/dark mode and accent color.
  **AI prompts** offers editable defaults with restoration controls.
- Tentative invitations use subdued neutral backgrounds and hatching, clearly
  separated from accepted meetings in either theme.
- The mini-calendar has independent month arrows. Sidebar shortcut clutter
  and the redundant saved-calendar reload button are removed.
- Every displayed day of a multi-day all-day meeting opens the same details,
  including the first day; calendar card identities are scoped to their day.
- New-event controls have less explanatory text, consistent option icons and
  more compact category color choices.
- Meeting details keep the organizer and company logos, with names on hover
  and required/optional roles in expanded participant details.
- Chat, commands and settings use compact icon entry points.

## Recover connections and retire stale recommendations

Saved WorkIQ, WebIQ and GitHub connections automatically retry recoverable
network failures, throttling, closed transports and expired MCP sessions.
The delay grows from 30 seconds to 15 minutes and is shown in connection status.
Transient initial isolated AI connection failures use the same policy.

Success resets the backoff. Cancellation and disconnect/forget stop automatic
recovery. A missing/rejected login, consent or permission problem still needs
user action; automatic retries never open a fresh interactive sign-in.
Recovery does not replay calendar writes or failed questions.

Copilot connectivity and Auto's Azure authentication now have separate status.
Auto authentication errors link directly to the connection dialog, with an
explicit device-code Azure sign-in button, a copyable code, a fixed Microsoft
link and cancellation. No interactive Azure login starts automatically, and
signing in does not resend a failed question. Quick and Thorough do not need
this extra login. A verified Azure login is not a promise of deployment access;
actual routing errors remain visible.

The notification bell refreshes live write availability. If a meeting changed
since a recommendation was created, the stale recommendation expires without
writing, the fresh event is cached and the engine may evaluate it again.
Uncertain previously submitted writes remain review-only and are never
automatically retried.

## Download and upgrade

Download `Tomlook-v0.6.0-win-x64.zip`, extract it, and run `Tomlook.exe`.
This is a portable, unsigned Windows 10/11 x64 application, not an installer.
Its Windows file/product version is `0.6.0`. The archive includes the executable,
project license and third-party/font notices. `SHA256SUMS.txt` supplies checksums
for the executable and ZIP.

Fully exit Tomlook, including its tray instance, before replacing the executable.
Copy any ordinary in-memory chat answers you need first. Keep the existing
`%LOCALAPPDATA%\Tomlook` profile; do not delete it to upgrade.

The current [Microsoft Visual C++ v14 Redistributable (x64)](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)
and, for live AI, the separately installed Copilot CLI runtime are still needed.
See [native setup](https://github.com/tkubica12/ai-outlook/blob/v0.6.0/native/README.md)
for connection requirements.

## Verification scope and remaining limits

Offline regression coverage includes Follow approval and read-back, recap
eligibility/deduplication/source bounds, safe stale-recommendation migration,
manual checks while automatic preparation is paused, bilingual settings
geometry, clicks on every day of multi-day all-day cards, connection retry/error
classification and separate Auto authentication controls. Device-code checks
cover bounded output, complete-code parsing, cancellation, tenant-bound CLI
arguments and the absence of automatic question replay.

No live user calendar writes were performed during this work. Live transcript
and chat retrieval, tenant-specific permissions and generated live notes have
not been established by the offline checks. A live Azure device-code sign-in
was not performed during development. WorkIQ calendar access alone does
not guarantee transcript/chat access. This release does not claim all broader
live-provider, accessibility or long-run acceptance gates complete.
