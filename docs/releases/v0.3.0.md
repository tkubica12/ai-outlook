# Tomlook v0.3.0

This release simplifies Ask, adds a dockable native assistant window, and
introduces on-demand travel and category reviews. These are changes since
[v0.2.0](https://github.com/tkubica12/ai-outlook/releases/tag/v0.2.0).

## A simpler Ask that stays out of the way

- Ask now opens in a resizable right-hand dock, sharing the meeting-detail
  slot instead of covering the calendar with a popup.
- Detach Ask opens a real, movable Windows window with its own taskbar entry.
  Dock Ask brings it back. Both views share the same question and answer.
- More options, local-concept editors and the optional proposal-mode controls
  are removed. Ask is for questions, formatted answers and retrieved sources.
- Hiding Ask, closing its detached window or switching between docked and
  detached views preserves a running question and unsent text. Only Stop
  requests cancellation; Exit still shuts down the application and workers.
- A quiet header status shows a running question or an unread answer.
  Ordinary answers are separate from the recommendation bell.
- Calendar selection never silently retargets Ask. The meeting context is
  explicit and stays fixed while a question runs. Changed meeting/account
  snapshots still invalidate stale output.
- Switching language preserves the current request and answer. Future
  questions use the newly selected language.

## Seven built-in slash commands

Commands appear below the question editor with short English/Czech
descriptions. Typing filters the list; Up/Down selects, Tab completes, and
clicking a row completes it. Completion does not submit a model request.
Enter or Ask submits; Shift+Enter adds a line. Escape first dismisses command
suggestions, then hides Ask without cancelling the question.

| Command | Purpose |
| --- | --- |
| `/today` | Summarize today's calendar and preparation needs. |
| `/week` | Summarize important meetings in the current calendar week. |
| `/prepare` | Explain preparation for the explicitly selected meeting context. |
| `/conflicts` | Explain this week's conflicts and possible resolutions. |
| `/find <text>` | Find a meeting, message or preparation material. |
| `/travel` | Review missing travel time before and after upcoming meetings. |
| `/categories` | Review upcoming meetings' category assignments. |

The first five expand into read-only questions. `/prepare` needs a meeting
context and `/find` needs search text; neither schedules anything automatically.

## Fourteen-day reviews, with results in the bell

- `/travel` and `/categories` take no arguments and cover the next rolling
  fourteen days, independently of the currently selected meeting.
- They enqueue typed, durable background work rather than asking the model
  to execute a slash command. Travel reviews publish only arrival/departure
  proposals; category reviews publish only category proposals.
- Results appear in the recommendation bell. Unrelated recommendations stay
  intact, duplicate requests share existing fresh research, and saved skips
  remain respected.
- Checks can run even when automatic preparation is paused. They retain the
  bounded queue, single background slot, daily budget and retry safeguards;
  new review work does not take the separate interactive question slot.
- Reviews require verified calendar coverage and matching connected accounts.
  Changing account or research configuration clears pending review intent
  rather than silently applying it to a different context.
- Eligible confirmed meetings are reviewed; cancelled meetings and existing
  logistics placeholders are excluded. Travel checks also exclude all-day
  events. Translation-only work cannot substitute for a fresh review.

These commands propose changes, not execute them. Calendar writes still need
the existing explicit approval and provider verification. Travel durations
remain estimates, and category choices come from the cached calendar categories.

## Responsiveness

The detached window uses a deferred native viewport and nonblocking shared
state. Typing there and unused partial Markdown updates no longer repeatedly
repaint the calendar. Final Markdown preparation remains on the AI executor;
the calendar, question submission and background review queue stay asynchronous.

## Download and upgrade

Download `Tomlook-v0.3.0-win-x64.zip`, extract it, and run `Tomlook.exe`.
This is a portable, unsigned Windows 10/11 x64 application, not an installer.
Its Windows file/product version is `0.3.0`. The archive contains only the
executable, project license and third-party/font notices; checksums are supplied
in `SHA256SUMS.txt`.

Fully exit Tomlook, including its tray instance, before replacing the executable.
Your existing `%LOCALAPPDATA%\Tomlook` profile remains separate from the archive;
do not delete it to upgrade.

The current [Microsoft Visual C++ v14 Redistributable (x64)](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)
is required. Neither it nor the separately installed Copilot CLI runtime is
bundled. See [native setup](https://github.com/tkubica12/ai-outlook/blob/v0.3.0/native/README.md)
for connection requirements.

## Verification scope and remaining limits

Native regressions cover command input, context/request routing, hide/dock/detach
lifecycle, the exact review horizon, background capacity, account binding and
scoped persistent recommendations. Local visual inspection of the earlier Ask
build covered docked and detached views in Czech/dark and English/light.
The final fourteen-day review path was exercised with a synthetic calendar and
fake executor, not a new live provider review or calendar mutation.
Final-release Computer Use inspection was unavailable in the current host.

These commands do not add free-form AI scheduling, autonomous calendar edits
or message sending. WorkIQ/WebIQ access still depends on account permissions,
connector availability and tenant policy. Broader live-provider, accessibility
and long-run acceptance gates are not claimed as completed by this release.
