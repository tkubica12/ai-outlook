# Tomlook v0.4.0

This release turns Ask into a cache-first, multi-turn AI chat, adds local fuzzy
calendar search, and introduces explicit Quick/Thorough profiles with
Microsoft-Decision-1 Auto routing. These are changes since
[v0.3.0](https://github.com/tkubica12/ai-outlook/releases/tag/v0.3.0).

## A real conversation in Ask

- Submitting a question clears the composer and adds a user bubble. The reply
  streams into its own bubble with a working indicator, elapsed time and factual
  tool activity, rather than leaving the submitted text in the editor.
- Follow-up questions receive bounded conversation context. Each meeting/global
  context retains its own draft and up to 32 turns in memory.
- Ask remains dockable or detachable into a real native window. Hiding it or
  switching calendar details does not cancel work or silently change its context.
- New chat, detach/dock and hide use compact icon buttons with accessible
  English/Czech labels, consistent with light/dark themes and the chosen accent.
- Quick questions can run while a Thorough investigation continues. Streaming,
  tool reads and final Markdown preparation remain off the calendar UI thread.

Tool activity describes actual operations; it is not a transcript of the
model's private reasoning. Ordinary chat history is not saved to disk and does
not survive application exit.

## Quick, Thorough and evidence-aware Auto

| Profile | Execution |
| --- | --- |
| Quick | GPT-6 Luna with low reasoning; 60-second execution bound. |
| Thorough | GPT-6.1 Sol with medium reasoning; ten-minute execution bound. |
| Auto | Microsoft-Decision-1 selects one of those fixed profiles. |

Session setup has a separate bounded deadline. Both profiles can use the same
narrowly allowlisted local and remote reads; host-enforced budgets differ.
There is no silent substitute if a model or reasoning effort is unavailable.

Auto uses Foundry's typed decision API directly, not another Copilot chat
session. Its instructions distinguish retrieving an explicit fact from
establishing a new relationship or obligation. A short question such as which
meeting needs a particular demo can require Thorough: a similar event title or
an invitation alone does not prove that the user is presenting. Calendar times,
locations, organizers, reading a named README and repeating verified findings
remain Quick. Explaining an uncertainty is different from investigating it.

Auto requires a separately configured Microsoft-Decision-1 deployment and an
existing authorized Azure CLI sign-in. Copy the credential-free
[`decision-router.example.json`](https://github.com/tkubica12/ai-outlook/blob/v0.4.0/native/decision-router.example.json)
into the private Tomlook profile and configure the endpoint, deployment,
CLI path, tenant and subscription. The deployment name can differ from the model
name. Foundry inference is billed separately from Copilot. Missing configuration,
authentication failures and invalid decisions produce explicit errors; manual
Quick/Thorough and offline commands do not require this router.

## Local cache tools and typo-tolerant search

- Both AI profiles can search the saved calendar, read a selected meeting and
  inspect saved Insights through typed Rust tools before making targeted remote
  reads. Results include coverage, freshness and stale-Insights information.
- Saved-calendar search uses a precomputed native index with case/diacritic and
  punctuation normalization, joined/split name matching, bounded spelling
  errors and adjacent transpositions.
- Results rank relevant candidates and expose which keyword matched which
  field, including approximate-match evidence. The model interprets the question,
  chooses keywords/date bounds, evaluates candidates and then answers.
- Full date ranges for multi-day meetings remain visible. Unknown or partial
  cache coverage is not treated as proof that a meeting does not exist.
- Cache snapshots are read-only and account-bound. Disk reads use bounded worker
  admission; these tools do not expose arbitrary SQL, shell or drive access.

The following slash commands run locally in Rust without any AI request, even
when Auto is selected or a cloud connection is unavailable:

| Command | Purpose |
| --- | --- |
| `/today` | Read today's saved calendar. |
| `/week` | Read the displayed week's saved calendar. |
| `/search <words>` | Run ranked fuzzy calendar search without Luna. |
| `/insights` | Read saved Insights for the explicit meeting context. |

`/find <text>` remains an AI question, not an alias for offline `/search`.
The existing `/prepare`, `/conflicts`, `/travel` and `/categories` commands
remain available. Fourteen-day travel/category reviews still put proposals in
the recommendation bell and never apply calendar changes without approval.

## Interrupted research and execution safeguards

Thorough work saves bounded findings and evidence in a private local
`ask-research.db`. Interrupted jobs can be explicitly continued from those
findings, or discarded after confirmation. Continuation is a new provider
request, not resumption of the original session. Changed accounts, meeting
snapshots or source bindings cannot silently reuse incompatible research.

These checkpoints can contain personal derived content and source excerpts;
they follow the Windows user's filesystem access and are not a claim of
encrypted conversation storage. They are separate from ordinary in-memory chat.
Cancellation, deadlines and read limits remain explicit; unfinished research
is not reported as a completed answer.

## Download and upgrade

Download `Tomlook-v0.4.0-win-x64.zip`, extract it, and run `Tomlook.exe`.
This is a portable, unsigned Windows 10/11 x64 application, not an installer.
Its Windows file/product version is `0.4.0`. The archive contains only the
executable, project license and third-party/font notices; checksums are supplied
in `SHA256SUMS.txt`.

Copy any ordinary chat answers you need before fully exiting Tomlook, including
its tray instance, to replace the executable. Keep the existing
`%LOCALAPPDATA%\Tomlook` profile; it is not part of the download and must not be
deleted to upgrade.

The current [Microsoft Visual C++ v14 Redistributable (x64)](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)
is required. Neither it nor the separately installed Copilot CLI runtime is
bundled. The fixed Ask models must be available to the isolated signed-in runtime.
See [native setup](https://github.com/tkubica12/ai-outlook/blob/v0.4.0/native/README.md)
for connection and Auto-router configuration.

## Verification scope and remaining limits

Native checks cover the chat lifecycle, concurrent execution profiles, cache
ownership/coverage, bounded tool reads, fuzzy ranking and research checkpoints.
The routing regression suite contains forty labeled requests, balanced between
Quick and Thorough. Against the configured Microsoft-Decision-1 deployment, the
old instructions selected 24/40 correctly; the repaired instructions selected
40/40, with no false-Quick or false-Thorough cases. A separate twelve-case
balanced set authored after the instructions were frozen also passed without
further tuning. The final forty-case run measured a warm routing median of
200 ms and p95 of 323 ms, excluding initial authentication and request pacing.
These are bounded regression results, not representative production accuracy or
an end-to-end answer-latency guarantee.

Live Quick and Auto checks also exercised typo-tolerant calendar lookup through
the actual model/tool path. Computer Use checks of the feature build covered
the native Ask interface, offline fuzzy search, meeting navigation and
light/dark presentation. They do not establish that every inferred commitment,
customer association or demo-readiness answer is correct.

WorkIQ/WebIQ/GitHub access still depends on account permissions, connector
availability and tenant policy. This release does not add autonomous calendar
writes, message sending or unrestricted filesystem access, and does not claim
all broader live-provider, accessibility or long-run acceptance gates complete.
